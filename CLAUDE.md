# CLAUDE.md — конфігурація ШІ-агента для проекту MIDI Redactor

Цей файл — головне джерело правил для Claude Code і його агентів (`.claude/agents/`), які працюють з репозиторієм.
Агент **зобов'язаний** прочитати його перед початком будь-якої задачі й дотримуватися його.
Якщо правило тут суперечить звичці агента — діє правило з цього файлу.

---

## 1. Мета проекту

Веб-застосунок для створення фортепіанних аранжувань під відео та музику.
Користувач завантажує відео та/або аудіо, слухає/дивиться його (зокрема сповільнено),
і паралельно в MIDI-редакторі (piano roll) записує ноти й педалі, прослуховує їх звуком фортепіано
та експортує результат у файл `.mid`.

Проект розробляється **повністю інструментами ШІ**: код, тести, документацію та плани пише агент,
людина (власник репозиторію) перевіряє плани й результат.

## 2. Функціональні вимоги

### 2.1 Аудіо
- [x] Завантаження аудіофайлу у форматах **mp3, wav, ogg, aac** (m4a з AAC теж приймається).
- [x] Після завантаження з'являється **аудіодоріжка з waveform** файлу.
- [x] Відтворення, пауза, перемотування (клік по waveform).
- [x] Зміна швидкості відтворення (сповільнення і прискорення, мінімум діапазон 0.25×–2×) **без зміни висоти тону**.
- [x] Некоректний формат → зрозуміле повідомлення про помилку.

### 2.2 MIDI-редактор (центр екрану)
- [x] Piano roll розміщений у центрі екрану: вертикально — клавіатура фортепіано (88 клавіш, A0–C8), горизонтально — час.
- [x] **Додавання** нот (клік/протягування на сітці).
- [x] **Видалення** нот.
- [x] **Зміна** нот: переміщення по часу й висоті, зміна тривалості, зміна velocity.
- [x] Прив'язка до сітки (quantize) з вибором кроку; темп (BPM) і розмір такту.
- [ ] Виділення кількох нот, undo/redo.
- [x] Натискання на клавішу віртуальної клавіатури програє відповідну ноту.

### 2.3 Педалі фортепіано
- [x] Окрема доріжка (lane) під piano roll для педалей.
- [x] Педаль **sustain** (MIDI CC64) — обов'язково; **sostenuto** (CC66) і **soft/una corda** (CC67) — бажано.
- [x] Додавання, видалення та зміна інтервалів натискання педалі (натиснута від–до).
- [x] Педаль впливає на програвання (sustain подовжує звучання нот).

### 2.4 Відтворення нот
- [x] Програвання нот із редактора **звуком фортепіано** (семпли акустичного фортепіано).
- [x] Play / Pause / Stop, курсор відтворення (playhead), старт з довільної позиції.
- [ ] Відтворення MIDI синхронізоване з аудіо та відео (спільна часова шкала).

### 2.5 Відео
- [x] Завантаження відеофайлу (мінімум mp4/webm).
- [x] Пауза / відтворення.
- [x] Прокрутка (перемотування) по часу.
- [x] Зміна швидкості відтворення.
- [ ] Синхронізація з таймлайном редактора (аранжування "під відео").

### 2.6 Експорт
- [ ] Завантаження (download) результату роботи у форматі **`.mid`** (Standard MIDI File), включно з нотами, velocity, педалями (CC-події) і темпом.
- [ ] Експортований файл коректно відкривається у сторонніх програмах (перевіряється тестом повторного читання файлу).

## 5. Робочий процес (обов'язковий)

Задачі виконуються **строго по черзі**, по одній.

### 5.1 Ролі (три агенти)

Роботу виконують три спеціалізовані агенти. Їхні визначення лежать у `.claude/agents/`.
Головна сесія (оркестратор) по черзі запускає агентів і передає між ними результати. Сама вона не пише ні планів, ні коду задачі.

| Агент | Файл | Що робить | Чого НЕ робить |
|---|---|---|---|
| **planner** | `.claude/agents/planner.md` | Пише і виправляє план `docs/plans/NNN-назва.md` | Не пише код, не змінює нічого поза `docs/plans/` |
| **plan-reviewer** | `.claude/agents/plan-reviewer.md` | Перевіряє план і виносить вердикт **ПРИЙНЯТО / ВІДХИЛЕНО** у `docs/plans/NNN-назва.review.md` | Не редагує план, не пише код |
| **implementer** | `.claude/agents/implementer.md` | Реалізує схвалений план: гілка, код, тести, коміти, merge, push | Не змінює план і не реалізує неприйнятий план |

### 5.2 Цикл задачі

1. **План.** Оркестратор запускає `planner` з номером і назвою задачі з розділу 8.
   Planner створює `docs/plans/NNN-коротка-назва.md` за шаблоном з розділу 6 і ставить статус `на рев'ю`.
2. **Рев'ю.** Оркестратор запускає `plan-reviewer`. Той записує вердикт у `NNN-коротка-назва.review.md`.
   - **ВІДХИЛЕНО** → оркестратор передає зауваження `planner`, той виправляє план, і план знову йде на рев'ю.
     Якщо за **3 раунди** план не прийнято, оркестратор зупиняється і питає власника.
   - **ПРИЙНЯТО** → оркестратор ставить плану статус `схвалено`. Підтвердження власника **не потрібне**.
3. **Автоматичний режим.** Розробка повністю автоматизована: власник не схвалює плани,
   а переглядає плани, вердикти рев'ю й коміти постфактум. Якщо власник пише зауваження чи правки,
   вони мають пріоритет: оркестратор передає їх `planner` (для майбутніх задач) або створює окрему задачу `fix/...`.
4. **Реалізація.** Оркестратор запускає `implementer` зі шляхом до схваленого плану. Implementer виконує кроки 5–10 нижче.
   Якщо під час реалізації з'ясовується, що план треба суттєво змінити, implementer зупиняється і описує проблему.
   Тоді план повертається до `planner` (крок 1).
5. **Гілка.** Від актуального `main` створити гілку `feature/NNN-коротка-назва` (виправлення — `fix/...`).
6. **Код** згідно з планом. Дрібні відхилення від плану дозволені, але їх треба пояснити у звіті.
7. **Тести.** Кожен етап включає написання тестів і **їх запуск**. Усі тести (backend + frontend), лінтери й перевірка типів мають проходити.
   Заборонено видаляти, пропускати (`skip`) або послаблювати тести, щоб вони "пройшли".
8. **Коміти** — невеликі, логічні, у форматі Conventional Commits англійською:
   `feat: ...`, `fix: ...`, `test: ...`, `docs: ...`, `refactor: ...`, `chore: ...`.
9. **Злиття.** Після зелених тестів: `git checkout main && git merge --no-ff feature/...`, повторний запуск тестів на `main`, `git push origin main` (і гілки).
10. **Звіт.** Коротко описати, що зроблено, результати тестів і відхилення від плану.
    Відмітити виконані пункти `[x]` у розділі 2 цього файлу, поставити статус задачі в розділі 8 і статус плану `виконано`.
    Оркестратор переказує звіт власнику коротко (2–5 рядків).
11. **Наступна задача.** Одразу після звіту оркестратор бере наступну задачу з розділу 8 і починає з кроку 1, не чекаючи власника.
    Так триває до кінця дорожньої карти.

### 5.3 Коли зупинитися й покликати власника

Автоматичний цикл переривається **лише** в таких випадках:
- план не прийнято за 3 раунди рев'ю;
- implementer з'ясував, що план суттєво нездійсненний, і planner двічі поспіль не зміг його виправити;
- тести чи збірка падають, і за 3 спроби виправити не вдалося;
- потрібна дія, яку агент не може або не має права виконати: встановлення системних пакетів (`sudo`), автентифікація, платні сервіси, force-push, видалення даних поза проектом;
- дорожню карту виконано.

У такому разі оркестратор коротко описує проблему, що вже спробувано, і варіанти рішення.

### Git
- Remote: `origin` → `git@github.com:budulka/midi_redactor.git` (SSH; сторінка — https://github.com/budulka/midi_redactor)
- Дозволи для команд задані в `.claude/settings.json`: git, uv, npm тощо дозволені, а force-push, `sudo` і `rm -rf` поза проектом заборонені.
- Основна гілка: `main`. Прямі коміти в `main` заборонені (крім початкового налаштування репозиторію).
- Ніколи не використовувати `git push --force` у `main`, не переписувати історію `main`.
- Не комітити: `node_modules/`, `.venv/`, `__pycache__/`, збірки, завантажені користувачем медіафайли, секрети.

## 7. Правила якості коду

- Код, ідентифікатори, коміти — **англійською**. Документація, плани та спілкування з власником — **українською**.
- TypeScript у режимі `strict`; без `any` без крайньої потреби.
- Python — з анотаціями типів, Pydantic-моделі для всіх даних API.
- Уся музична логіка (конвертація часу ↔ тіки ↔ такти, квантизація, робота з нотами) — у чистих функціях, покритих unit-тестами.
- Єдине джерело правди про час — секунди на спільному таймлайні; MIDI-тіки обчислюються з темпу при експорті.
- Модель даних проекту (узгоджується між frontend і backend):
  - `Note { id, pitch (21–108), start (с), duration (с), velocity (1–127) }`
  - `PedalEvent { id, type: "sustain" | "sostenuto" | "soft", start (с), end (с) }`
  - `Project { bpm, timeSignature, notes[], pedals[] }`
- Великі медіафайли (аудіо/відео) обробляються в браузері (Object URL), на backend без потреби не завантажуються.
- Не залишати закоментований код, `console.log`/`print` для налагодження, TODO без пояснення.
